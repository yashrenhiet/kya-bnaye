# ADR 001: Flutter for both Android and iOS

**Status:** Accepted — 2026-09-26

## Context
Indian households are overwhelmingly Android (~95% market share), but the primary
developer's own phone and dev machine are iOS/macOS. The app needs to reach both
platforms without maintaining two separate codebases as a solo/part-time project.

## Decision
Build with **Flutter (Dart 3, stable channel)**, targeting Android and iOS from one
codebase.

## Alternatives considered
- **React Native / Expo** — comparable reach, large ecosystem (and what one of the
  researched prior-art apps, `Pantry`, migrated to). Rejected in favour of Flutter for
  stronger typing (sound null safety, no `any`-typed JS interop by default) and a single
  toolchain (Dart) instead of JS/TS + native modules.
- **Kotlin Multiplatform** — shares only business logic, still requires two native UIs.
  More native polish per platform, but roughly double the UI work for a part-time solo
  project. Rejected for now; could revisit if native-only APIs become a hard requirement.
- **Native SwiftUI only** — rejected outright: misses ~95% of the target audience
  (see `docs/RESEARCH.md`, Platform note).

## Consequences
- One shared UI codebase; platform-specific code isolated to `android/` and `ios/`
  folders generated by `flutter create`.
- Team needs Dart proficiency, not Kotlin/Swift, for day-to-day feature work.
- iOS builds still require a Mac + Xcode (available — see `AGENTS.md` §9).
